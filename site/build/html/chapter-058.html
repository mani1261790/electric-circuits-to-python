第58章　atomic操作とmemory model

58.1 loadとstoreの間を閉じる

普通のloadとstoreを二命令に分けると、別coreが間へ割り込める。atomic read-modify-write（原子的な読み出し・変更・書込み）は、比較と更新を一つのlinearization pointで行う。compare-and-swap（CAS）は、memoryが期待値eならdを書き、違えば書き換えず失敗を返す。

RISC-VではA拡張のLR/SCやAMOが候補になるが、atomic extensionを必須にしないrv32eduへ既成事実として混ぜない。spin lockはCASまたはLR/SC、lock取得後のdataアクセス、releaseの順序を別々に記録する。

58.2 memory modelの三つの層

ISA memory modelは命令列で許される観測を、compiler memory modelは最適化が保つ順序を、language memory modelはthreadから見えるhappens-beforeを定める。同じstoreという語でも、各層の契約は同一ではない。fenceは特定の前後関係を狭めるが、cache coherenceそのものを置き換えない。

store bufferingでは、thread 0がx=1; r0=y、thread 1がy=1; r1=xを実行する。両方のreadが0になることを許すかは、対象modelとfenceに依存する。結果を「実機で起こった」と言うには、CPU、compiler、optimization、core配置を固定する必要がある。

58.3 予定実験

予定simulatorはthread, operation, address, value, order, fence, observation, linearization_point, status, source_kind, measuredを保存し、fenceなし／ありの許容結果集合を比較する。CAS失敗は通常の分岐であり、memory corruptionではない。lockのunlockではrelease、lockではacquireの境界を明記する。

固定runnerの解析・契約再生は完了しているが、RV64 QEMUや実CPUで実行した結果ではない。Verilator/Yosysは候補RTL、SPICEはatomic orderingには不適用、FPGAは任意のreference board経路として分離し、外部経路はplannedのまま扱う。次章では、これらの依存順をcore内部で隠すout-of-order実行へ進む。

58.4 CASを一つのlinearization pointで追う

lock wordの初期値を0、取得側の期待値を0、書込み値を1とする。次の二つのthreadが同時にCASを発行した場合、memoryへの比較と更新を別々の行にしてはいけない。

順序T0T1lock word結果
0——0free
1CAS(0→1)—1T0 success、linearization point
2—CAS(0→1)1T1 fail、値は変更しない
3store 0 (unlock)—0releaseの境界
4—CAS(0→1)1T1 success

T1のCASが「期待値が違ったので失敗」と返すのは正常な競合であり、再試行ループが必要かどうかはlockの契約で決める。比較後のstoreだけを別transactionにすると、T0とT1の両方がsuccessになり、critical sectionへ二者が入る。runnerではlinearization_pointを一つだけ許す不変条件にする。

memory modelの条件変更も同じtraceで比べる。x=y=0からT0がx=1; r0=y、T1がy=1; r1=xを走らせ、fenceなしの候補結果r0=0,r1=0と、両store後のloadを順序付けたfenceありの候補集合を別行に保存する。これは許容集合の比較であって、特定CPUでその結果を測った証拠ではない。

故障診断では、CASが二回成功するならatomic操作の分割、両threadがlock後のdataを古い値で読むならacquire/release境界、compilerが命令を並べ替えたならlanguage/compiler層を確認する。次章では、こうした依存を命令単位で追い、実行順とretire順を分離する。

故障診断の手順

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • unaligned_cas: 入力はaddress 0x2002 for 32-bit CAS。期待する診断はatomic_alignment_rejectedで、正常値として続行しない。
  • unknown_fence: 入力はfence mode absent from declared model。期待する診断はunsupported_fence_rejectedで、正常値として続行しない。
  • split_rmw: 入力はCAS implemented as independent load/store。期待する診断はnon_atomic_rmw_rejectedで、正常値として続行しない。
  • model_claim: 入力はrelaxed result called a measured hardware fact。期待する診断はprovenance_boundary_rejectedで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
