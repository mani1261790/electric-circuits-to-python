第55章 演習解答

E1 cache lineとaddress分解

0x2c=44なので、block addressは44//16=2、offsetは44 mod 16=12。setは2 mod 4=2、tagは2//4=0である。offset 4 bit、set index 2 bitを先に取り、残り26 bitをtagとする。ここでaddressはbyte単位であり、word addressへ読み替えない。

E2 direct-mapped set

0x00,0x40,0x80,0xc0 はそれぞれblock 0,4,8,12で、どれも block mod 4=0、したがってset 0である。各blockは同じ一つのline位置を使うため、交互に読むと前のlineをevictしてhitにならない。これは容量不足一般ではなく、このgeometryのconflict missである。

E3 row-major

16 B lineにはint32が4個入る。64要素は16 lineを一度ずつ初めて読むのでcompulsory missが16回、その後の各line内の3要素がhitになり、hitは48回。hit率は48/64=0.75である。これはcapacity 64 B、4 set、direct-mapped、初期emptyという代表入力からの解析予測であり、実行測定ではない。

E4 column-major競合

一行8要素×4 Bなので、同じ列の隣接要素は32 B離れる。block列は0,2,4,6,8,10,12,14となり、set列は0,2,0,2,0,2,0,2である。次の列でも同じblock列を別の要素として再訪するが、set 0と2には複数blockが集中し、各再訪前にevictされる。代表traceでは64 miss、0 hit、hit率0である。

E5 pointer chasing

8個のaddressは64 B刻みで、blockは0,4,8,12,16,20,24,28、すべてset 0へ写る。4 set direct-mappedは一つのsetに一lineしか置けないため、8個を一周する間に常に前のblockをevictする。2周16 accessでも16 miss、0 hitとなる。次addressがload結果で決まるため、hardwareが先読みできるとは限らず、同じaccess数だけでrow-majorと同じ局所性とは言えない。

E6 AMAT

AMAT = 1 + 0.25×50 = 13.5 ns。ここで50 nsは下位cache、主memory、queue待ちを含む一つのmiss penaltyとして定義済みなので、memory待ちをもう一度足してはいけない。実機の平均access時間と呼ぶには、実行trace、cache階層、clock、queueの測定条件が別途必要である。

E7 line size

16 B lineではE3と同じく16 miss、48 hit。8 B lineでは一lineにint32が2個入り、64要素は32 lineなので32 miss、32 hit、hit率0.5となる。容量は同じでも一度に運ぶ隣接要素が減るため、row-majorのspatial localityを活かすcompulsory missの単位が増えた。ただし別traceや別のassociativityでは結果が変わる。

E8 write policy

write-throughはstore hitでcacheと下位memoryを更新し、write-backはcache lineをdirtyにしてevict時に下位memoryへ書く。write allocateはstore missでlineを読み込んでからcacheを更新し、no-write-allocateはcache lineを作らず下位memoryへ直接書く方針である。本章の代表RTLはwrite-through・no-write-allocateを固定し、coherenceと複数coreの順序は扱わない。方針を変えたら同じstore traceを別caseにする。

E9 負のテスト

word addressをbyte addressとして渡す場合はaddress_unit_must_be_declared、line size=0またはset数=3はcache_geometry_rejected、offsetを捨てる前のtag比較はmapping_order_rejected、未宣言prefetchはundeclared_access_rejected、penalty二重加算はamat_accounting_rejectedとする。入力を黙って補正してhit率へ混ぜず、caseごとfail closedにする。

E10 RTL data cacheと次章への橋

最低限、cycle、request_id、cpu_address、operation、hit_or_miss、set、tag、evicted_tag、dirty、memory_request、refill_word_index、response、status、source_kind、measuredを保存する。16 B lineなら4 wordを順序付きでrefillし、最後のwordでline validを立てる代表契約にする。次章へはvirtual_address、physical_address、page_number、offset、permission、tlb_hitを渡すが、permission faultをcache hitと数えない。
