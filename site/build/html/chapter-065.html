第65章　永続storageの物理とcontroller

65.1 電源を切っても残るbit

RAMのcellは電源がなくなると、保持していた電荷や帰還状態を失う。一方、永続storage（persistent storage）は、電源を切った後も読み出せる物理状態を作る。bitという記号が媒体の中にそのまま浮かんでいるわけではない。HDDでは磁性体の磁化方向、SSDでは絶縁膜に閉じ込めた電荷によるしきい値の違いを、controllerが電圧や磁気の読み出し結果から論理値へ分類する。

HDDは回転する platter、磁気ヘッド、track、sectorを使う。要求された場所が現在のhead位置から遠いほどseek時間が増え、回転待ちも加わる。したがって同じbyte列でも、要求順序によって時間が変わる。本章のdisk模型では、物理的な回転波形は再現せず、track距離と固定の回転penaltyを分けて記録する。

65.2 SSDのpageとerase block

NAND flashでは、readの単位、programの単位、eraseの単位が同じではない。教育用の代表模型では、pageを4 KiB、erase blockを8 pageとする。pageへprogramした後、同じ場所を上書きするには、新しいpageへ書き、古いpageをinvalidとする。blockを再利用するには、まだ有効なpageを別の場所へコピーしてからblock全体をeraseする。

この違いがSSDのcontrollerを必要にする。hostはlogical block address（LBA）を指定するが、NANDのphysical pageを直接指定しない。controllerはLBAからphysical pageへのmapping、valid bit、erase count、busy状態を管理する。mappingの内容はデータそのものと同じくらい重要で、電源断の途中に新しい対応だけを記録すると、古いデータも新しいデータも失う可能性がある。

65.3 FTL、wear leveling、garbage collection

flash translation layer（FTL）はLBAを物理配置へ変換する。順番に書くsequential writeなら空きpageへ追記しやすい。既存LBAを飛び飛びに更新するrandom writeなら、古いpageがinvalidになり、空きpageが減る。garbage collection（GC）は、有効pageを別blockへ移して、invalid pageを含むblockをeraseする処理である。

hostが8 pageを書いたとき、GCで4 pageを移し、計12 pageを媒体へprogramしたなら、write amplificationは

WAF = 媒体へ書いたbyte数 / hostが要求したbyte数 = 12 / 8 = 1.5

となる。これは寿命と書込み時間の模型であり、特定SSDの保証値ではない。wear levelingは特定のhot LBAだけが同じblockをeraseし続けないよう、erase回数の少ないblockも候補にする方針である。温度、NAND世代、予備領域、ECCなどを固定しないまま寿命を数値化してはいけない。

65.4 requestからcompletionまで

controllerは、hostのrequestを受けると、idle、busy、programまたはread、completionという状態を進む。queue深さ1のtoy controllerなら、busy中に二つ目を受理しない。completionにはrequest id、LBA、物理page、status、媒体へのbyte数を残す。これがなければ、遅い原因がseek、page program、GC、bus待ちのどれか分からない。

予定実験では、track 50から要求列40, 10, 70, 20を処理する。FCFSの移動距離は150、SSTFは100（50→40→20→10→70）になるという解析予測を先に保存する。SSDでは、順次更新とLBA 1を二度更新する列を同じJSONL schemaで流し、valid pageとerase countを追跡する。ここまでの数値は実行済み測定ではなく、runnerが出すべき期待値である。

65.5 電源断を成功扱いしない

programが終わった直後、mapping commitの前に電源断したとする。回復方針を「旧mappingを保持」と固定すれば、LBA 0は旧physical page 8を指し続ける。新page 12が媒体上に存在することだけを根拠に、新しいmappingを成功扱いしてはいけない。実製品ではjournal、metadata copy、電源保護など別の契約が必要である。

次章では、storageそのものではなく、外から入ってくるkey操作を追う。そこでもcontroller、protocol、queue、statusという同じ境界が現れる。trackとpageの物理詳細から、byte列を扱う入力経路へ進む。

65.6 diskとSSDを同じ「要求→完了」で比較する

磁気diskの代表値は初期head=50、要求列[40,10,70,20]である。FCFSは50→40→10→70→20なので移動距離は10+30+60+50=150、SSTFは毎回最短を選び50→40→20→10→70なので10+20+10+60=100となる。これは固定rotation penaltyを含むtoy条件の解析値であり、実diskのlatencyではない。

SSDのsequential caseではpage size=4096 B、free physical page=[8,9,10,11]、LBA=[0,1,2,3]をappendする。LBA 1をpage 20、次にLBA 3を21、さらにLBA 1を22へ更新すると、newest-onlyのmappingは{0:8,1:22,2:10,3:21}で、9と20はinvalid pageとしてGC候補になる。host bytesは16,384 Bでも、metadata移動やGCを含めるかでmedia bytesは変わる。

状態表を自分で作る

本文を読み終える前に、次の五列を紙またはテキストへ写す。『層』『入力』『内部状態』『上位の契約』『破綻条件』である。層には物理量、数値模型、回路、命令、OS、処理系のどれかを入れ、同じ名前の量を別層で使うときは型と単位を併記する。

内部状態から上位の契約へ進むとき、隠した変数を一つ選ぶ。たとえば連続電圧を論理値へ写すなら、しきい値の近くの電圧と雑音を隠している。命令列を関数呼出しへ写すなら、レジスタやstack pointerを隠している。隠した変数が変化しても契約が保たれる範囲が、その抽象化の強さである。

次に、同じ表へ失敗時の値を書く。未定義電圧、負の容量、範囲外アドレス、stack underflow、権限違反などは、正常なゼロや空文字へ丸めない。失敗を早い層で止め、診断名と入力を保存しておくと、後で別の層の故障と取り違えにくい。

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • lba_out_of_range: 入力はlba=999 for a 64-page device。期待する診断はinvalid_lba_rejectedで、正常値として続行しない。
  • page_block_unit_mismatch: 入力はbyte address passed where page index is required。期待する診断はaddress_unit_mismatchで、正常値として続行しない。
  • torn_mapping_record: 入力はpower loss between program and mapping commit。期待する診断はold_mapping_retained_or_recovery_requiredで、正常値として続行しない。
  • hidden_gc: 入力はmedia write count changes without a declared GC event。期待する診断はprovenance_incompleteで、正常値として続行しない。
  • illegal_erase: 入力はerase nonempty block without valid-page migration。期待する診断はdata_loss_path_rejectedで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

  • 受け取る: 前章で定義した入力を受け取る
  • 渡す: 次章へ検証済みの状態を渡す

渡す値には、値だけでなく単位、版、source kind、status、measuredフラグを付ける。後章で同じ記号が現れたとき、初出の定義と再利用の条件を辿れるようにする。

模型の境界を言葉にする

  • HDDの磁区とSSDのcellは物理状態の説明用模型であり、特定製品の媒体構造や寿命を保証しない。
  • FTLのmapping・GC・wear levelingは小さな教育模型で、実製品のover-provisioningやNAND failure modeを網羅しない。
  • latencyは明示したqueue・seek・page program条件からの解析予測であり実測値ではない。
  • 電源断時のatomicityと耐久性はcontroller仕様と電源保護回路を固定しない限り主張しない。

境界を知ることは、式を弱めることではない。式が成立する条件を明示すれば、次により詳しい模型や測定へ進む理由を説明できる。逆に、条件を隠したまま桁の多い数値を出すと、精度ではなく誤解だけが増える。

最後に、代表実験を見ずに三つの文を書く。第一文は入力と単位、第二文は内部状態から出力までの一つの変化、第三文は最も近い破綻条件である。三文が書けたら、対応するartifactとrunnerの行を開き、本文の説明と同じtrace ID・statusになっているか照合する。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。
