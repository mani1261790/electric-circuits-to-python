第44章　stored-program machineとISA

44.1 回路を変えずに計算を変える

第43章のmemory arrayは、命令を特別扱いしないbyte-addressed storageである。stored-program machineは、そのmemoryに命令のbit列とデータを置き、同じdatapathが命令を順番にfetch、decode、executeする。加算器やregisterを別の回路へ交換しなくても、memory中の命令列を変えれば計算の手順が変わる。

ここでは学習用の16-bit固定長命令、16-bit register、8本のregister（r0〜r7）、byte-addressed memoryを定義する。r0は常に0で、書込み先に指定された場合も変化しない。命令の格納もlittle-endianで、PCはbyte address、通常の命令後は2 byte進む。

機械のarchitectural stateは次の組である。

S = (pc, r[0..7], memory[0..255], halted, fault)

reset後はpc=0、全register=0、halted=false、fault=noneとする。1ステップは、memory[pc]とmemory[pc+1]を命令wordとして読むfetch、opcodeとfieldを読むdecode、状態を変えるexecute/writebackからなる。faultまたはHALT後は勝手に次の命令へ進まない。

44.2 極小ISAの命令形式

この章のopcodeは4 bitで、上位から次の形式を取る。

opcode命令bit field意味
0x1ADD rd,rs1,rs2rd[11:9], rs1[8:6], rs2[5:3], [2:0]=0rd=(rs1+rs2) mod 2^16
0x2ADDI rd,rs1,imm6rd[11:9], rs1[8:6], imm6[5:0]符号拡張したimmを加算
0x3LOAD rd,[base+off6]rd[11:9], base[8:6], off6[5:0]16-bit little-endian load
0x4STORE rs,[base+off6]rs[11:9], base[8:6], off6[5:0]16-bit little-endian store
0x5BEQZ rs,rel9rs[11:9], rel9[8:0]0ならpc_next + 2*sign_extend(rel9)
0xfHALT残りは0実行を停止

未定義opcode、予約bit違反、奇数アドレスの16-bit load/store、memory範囲外はfaultにする。ADDIのimm6とBEQZのrel9は二の補数として解釈する。BEQZの相対値の単位は命令数であり、byte addressへ変換するときだけ2倍する。このようにfield幅、符号、PC単位を仕様へ書かなければ、同じhex wordをdecodeできない。

44.3 fetchからwritebackまで

例えばPC=0で0x2207をfetchする。上位opcodeは2、rd=1、rs1=0、imm6=7なので、r1=0+7を書き、次のPCを2にする。次の命令が0x2405ならr2=5となる。ADDはr1とr2をreadし、ALUで加算し、r3へwriteする。書込み時にもrd=0なら無視してr0を守る。

LOADとSTOREは第43章のmemory interfaceへ接続する。LOADはbase+sign_extend(off6)をbyte addressとして要求し、2 byteの整列、latency、response handshake、faultを引き継ぐ。STOREはregisterの16 bit値をlittle-endianの2 byteへ分ける。命令fetchも同じarrayから2 byteを読み出すため、instructionとdataの領域をどこに置くかはprogramのmemory mapの責任になる。

BEQZでは、まず通常の次PC pc_next=pc+2を作り、条件が真ならpc_next + 2*rel9へ置き換える。例えばPC=0x0008のBEQZ r1,+2でr1=0なら、次の命令のPC=0x000aから4 byte進んで0x000eへ移る。r1が非零なら0x000aへ進む。branch targetが命令境界やmemory範囲にない場合は実行せずfaultにする。

44.4 二つのprogramを同じmachineで動かす

Program Aは7と5を加える。

address  word       assembly
0x00     0x2207     ADDI r1,r0,7
0x02     0x2405     ADDI r2,r0,5
0x04     0x1650     ADD  r3,r1,r2
0x06     0xf000     HALT

fetchのたびにPCは00,02,04,06と進み、HALT時にr3=0x000cとなる。これは加算器の配線を変えた結果ではなく、命令wordがALUの入力とwrite先を選んだ結果である。

Program Bはmemoryへ42を書き、同じ場所をloadして6を加える。

address  word       assembly
0x00     0x222a     ADDI r1,r0,42
0x02     0x2406     ADDI r2,r0,6
0x04     0x4210     STORE r1,[r0+0x10]
0x06     0x3610     LOAD  r3,[r0+0x10]
0x08     0x18d0     ADD   r4,r3,r2
0x0a     0xf000     HALT

Program Bのstore後、memory[0x10]=0x2a、memory[0x11]=0x00であり、load後にr3=42、HALT時にr4=48となる。Program AとBは同じregister、ALU、PC、memory interfaceを使うが、memoryに置いたword列が異なる。

44.5 Python参照模型と出所

実装済みの固定Python runnerは、命令wordのencode/decode関数とstep(state)を別に持つ。encodeが作ったwordをdecodeへ戻してfieldが一致すること、stepがPC、register、memory、faultを更新することを検査する。Program AとBのtraceには各stepのpc_before、word、decoded operation、変更register、memoryアクセス、pc_afterを保存する。固定runnerの契約再生は完了しているが、formal検査と実CPU・実測は別の未実行経路である。

予定formal検査では、有限のmemoryと全opcode表に対し、r0不変、HALT後不変、未定義opcodeのfault、ADDの16-bit wrapをassertする。これはこの小さな状態空間の論理契約であり、実CPUの電力、速度、cache、割込みを測定するものではない。

44.6 von NeumannとHarvard

命令とデータを同じmemory空間・同じ経路で扱う構成をvon Neumann型、命令memoryとdata memoryを別の経路へ分ける構成をHarvard型と呼ぶ。前者はmemory mapとbusを一つに保ちやすい反面、fetchとload/storeが同じportを争う。後者は同時アクセスを許しやすい反面、二つのaddress空間、初期化、整合性の契約が増える。本章の16-bit模型はvon Neumann型であり、Program Bのfetchとdata accessが同じ256 byte arrayを共有する。Harvard型では命令側へstoreして次の命令を書き換える場合の整合性が別問題になり、単に二つの配列へ分ければ同じtraceになるわけではない。

どちらが「速い」と決めつけず、port数、同時要求、命令書換えの可否、bus arbitration、traceのinstruction_memory/data_memory欄を比較する。Harvardへ変更する場合は、ISAの命令結果だけでなく、memory interfaceとfault domainを新しい仕様として固定しなければならない。

44.7 ISAから次へ

ISAはhardwareの内部配線そのものではなく、programが観測できる命令、register、memory、例外、初期状態の契約である。encodingを変更すればdecode回路も変わるが、同じ契約を保つ限り、実装は単一cycleでもpipelineでもよい。次章では、この教育用16-bit ISAで固定した「instruction wordをdecodeして状態を更新する」という考え方を、標準化されたRISC-V RV32Iの形式へ写像する。

本節で示すprogram結果は、上に明記した有限模型から導いた手計算の解析上の期待値である。固定runnerは入力由来の契約を再生済みだが、これは実行済みtraceや実CPUの性能・実測値ではない。

5　模型の境界と章間の橋

この章の模型は、適用範囲を明示して初めて安全に使える。次の限界を一つずつ、本文のどの主張に効くかと一緒に読む。

  • 16-bit命令・16-bit register・8本のregisterは教育用custom ISAでありRV32Iそのものではない。
  • memoryは256 byteの有限模型で、cache・割込み・pipeline・仮想memoryを含まない。
  • program結果は指定した命令列を手計算した期待値であり、runner実行結果ではない。
  • fault方針は未定義opcode・範囲外・整列違反をfail closedにする一例である。
  • 本章の固定runnerは契約を再生済みだが、formal・測定は未実行・未取得である。

  • 第43章のbyte-addressed memory、bank、endianness、valid-ready、latency、第39章のstate、第32章の検証を受け取る。

次章へ渡すもの:

  • 第45章へ、instruction encoding・register・PC・load/store・faultというcustom ISAの観点をRV32Iへ渡す。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。

11　次章の読者への引き継ぎ文

最後に、次章の読者がこの章を読み返さなくても前提を再構成できる引き継ぎ文を書く。第一文はこの章が固定した定義、第二文は代表入力と途中状態、第三文は守る不変条件、第四文は最も近い破綻条件、第五文は未実行または未照合の境界である。

引き継ぎ文の主語を『この値は』だけにしない。『この模型では』『この版のtoolでは』『このmemory領域では』『このsource spanでは』のように、値の所有者を明記する。所有者が変わるところが、章間のbridgeであり、独立レビューが最初に読む境界である。

引き継ぎ文を書いたら、manifestの bridge_in と bridge_out、handoffのopen question、required artifactを照合する。本文に書いた橋と台帳の橋が異なる場合は、どちらかを勝手に合わせず、差分を未解決として残す。
