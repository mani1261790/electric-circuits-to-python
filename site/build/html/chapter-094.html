第94章　bytecode compiler、CFG、code object

94.1 ASTから命令列へ

compilerはAST nodeごとにvirtual machine命令を選ぶ。literalはconstant poolへ、nameはscopeに応じたlocal/global/free操作へ、operatorはoperandを積んだ後のbinary operationへ変換する。ifとwhileはlabelとconditional jumpを作るため、sourceの字下げをそのまま命令列へ写すのではない。

94.2 basic blockとCFG

basic blockは途中にbranch targetやbranchがない命令の連続である。CFG (Control-Flow Graph) のedgeは次に実行できるblockを表し、ifにはtrue/false、loopにはback edge、returnにはexit edgeを置く。labelを数値へ割り当てる前に、blockとedgeを表示するとjumpの向きを検査しやすい。

stack VMでは各opcodeのstack effectを記録する。branchの両側がjoinする地点でstack depthが一致しなければ、実行時に別のstack形状を読むことになる。verifierはunderflow、join不一致、未解決label、範囲外constant indexを拒否する。

94.3 code object

MiniPyのcode objectはbytecode、constant pool、name table、local table、argument count、line table、exception table候補を持つ。CPythonのcode objectと同じlayoutだと主張せず、共通する「実行に必要な静的情報」と実装固有fieldを分ける。line tableは例外とtraceをsource位置へ戻すために使う。

94.4 小さな例

if x: y = 1 else: y = 2は、xを読む、条件jump、二つのstore、joinという形になる。両branchのjoin時点でstackを空にする設計なら、その契約をcode objectへ残す。whileは条件blockへ戻るedgeを持ち、body内のbreakはexit blockへ接続する。

disassemblerはoffset、opcode、argument、source span、stack depthを一行ずつ表示する。CFG図とbytecodeを同じlabelで参照し、どちらかだけを正本にしない。第95章ではこのcode objectをframeとoperand stackで解釈する。

94.5 ifのstack depthとcode objectを検算する

if x: y = 1\nelse: y = 2をentry→then/else→joinへ分ける。entryがxをloadしてstack depth=1、then/elseが各storeで0、joinのin/out=0となる。片方のbranchだけ値を残すと、joinでstack shapeが一致しないためverifierが拒否する。

constant index 9（pool size 1）、invalid opcode 255、unresolved label L9、underflow、then/else join depth mismatchは、実行させずverifier errorへ分類する。compilerがASTを変換したという事実とVMで結果を得たという事実を分け、次章へcode objectを渡す。

状態表を自分で作る

本文を読み終える前に、次の五列を紙またはテキストへ写す。『層』『入力』『内部状態』『上位の契約』『破綻条件』である。層には物理量、数値模型、回路、命令、OS、処理系のどれかを入れ、同じ名前の量を別層で使うときは型と単位を併記する。

内部状態から上位の契約へ進むとき、隠した変数を一つ選ぶ。たとえば連続電圧を論理値へ写すなら、しきい値の近くの電圧と雑音を隠している。命令列を関数呼出しへ写すなら、レジスタやstack pointerを隠している。隠した変数が変化しても契約が保たれる範囲が、その抽象化の強さである。

次に、同じ表へ失敗時の値を書く。未定義電圧、負の容量、範囲外アドレス、stack underflow、権限違反などは、正常なゼロや空文字へ丸めない。失敗を早い層で止め、診断名と入力を保存しておくと、後で別の層の故障と取り違えにくい。

故障診断の手順

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • underflow: 入力はopcode consumes more stack values than available。期待する診断はstack_underflowで、正常値として続行しない。
  • join_mismatch: 入力はCFG join has unequal stack depths。期待する診断はstack_join_rejectedで、正常値として続行しない。
  • bad_label: 入力はunresolved or duplicate label。期待する診断はlabel_rejectedで、正常値として続行しない。
  • bad_pool: 入力はconstant/name index outside table。期待する診断はpool_index_rejectedで、正常値として続行しない。
  • bad_opcode: 入力はopcode not in MiniPy table。期待する診断はopcode_rejectedで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

模型の境界を言葉にする

  • MiniPy bytecodeは固定opcode subsetに限定し、CPython 3.14の全opcode・exception table互換を主張しない。
  • CFGはstructured if/while/functionの入口に限定し、最適化やSSAを扱わない。
  • bytecode/CFG/verifier出力は固定runnerで契約を再生済みだが、実機・外部toolの測定値ではない。

境界を知ることは、式を弱めることではない。式が成立する条件を明示すれば、次により詳しい模型や測定へ進む理由を説明できる。逆に、条件を隠したまま桁の多い数値を出すと、精度ではなく誤解だけが増える。

章末の自己確認

最後に、代表実験を見ずに三つの文を書く。第一文は入力と単位、第二文は内部状態から出力までの一つの変化、第三文は最も近い破綻条件である。三文が書けたら、対応するartifactとrunnerの行を開き、本文の説明と同じtrace ID・statusになっているか照合する。

この確認を通過しても、外部toolや実測器を使ったとは限らない。実行可能モデル、解析予測、実測、独立レビューは別の欄で管理する。その区別を保ったまま次章へ進むことが、この章の最後の成果物である。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
