第2章　演習

この章の演習は、計算量を競うものではない。各問で「何を観測し、どの契約を使い、何を隠しているか」を書く。book run は共通runnerの実行入口で、固定Linux環境の入力由来契約を再生する。外部domain toolや実機が未接続でも、runnerの契約結果、解析予測、測定欄 not_run を分けて台帳を作る。

E1　四つの言葉を分類する

次の文を、主な分類「自然法則」「理想化モデル」「設計上の契約」「特定実装」のいずれかへ分類する。分類しにくい文は、二つの主張へ分けてから答える。

  1. 電荷は消滅せず、閉じた系全体の電荷量は保存される。
  2. この1 kΩ抵抗器は、室温・直流・定格内なら I=V/R で近似できる。
  3. RV32IのADDは32ビットの和をrdへ書く。
  4. rv32eduのUARTデータレジスタは0x10000000にある。
  5. CPython 3.14.7では整数オブジェクトを複数の内部桁で表す。
  6. 二入力NANDは、入力が有効範囲ならY=NOT(A AND B)として読める。
ヒント
  • ヒント1: 「この部品」「このCPU」「この版」のような限定がある文は実装に近い。
  • ヒント2: 他の作り方でも守るべき結果を定める文は契約に近い。
  • ヒント3: 条件を省いて式を使いやすくしている文はモデルである。自然法則と同じ名前の式でも、適用範囲を確認する。

E2　抵抗器の台帳を一行作る

1 kΩの抵抗器に5 Vを加える。I=V/Rから5 mAを予測した。この予測について、次の欄を一つずつ埋める。

  • 下位表現
  • 上位契約または予測
  • 隠される変数を二つ以上
  • 成立条件を二つ以上
  • 破綻条件を二つ以上
  • 予測を確かめる最小の検証

最後に、「5 mA」は観測値か、モデルからの予測かを明記する。

ヒント
  • ヒント1: 下位表現には電位差と電荷の流れを含める。
  • ヒント2: 隠される変数には温度、寄生要素、許容差などがある。
  • ヒント3: まず電圧と電流を測り、V/Rとの差を誤差と条件に照らして比べる。

E3　抵抗器の自己発熱を診断する

同じ抵抗器へ5 Vを加え続けたところ、最初は5.0 mA、数分後は6.2 mAになった。電源電圧は測定中ほぼ5 Vだった。

  1. 観測事実を二つ書く。
  2. 「自然法則が破綻した」と言う前に、台帳のどの欄を見直すべきか。
  3. 追加すべき観測を二つ挙げる。
  4. I=V/Rを使い続けてよい条件を一つ、外れている可能性のある条件を一つ書く。
ヒント
  • ヒント1: 電力はP=VIであり、抵抗器は発熱し得る。
  • ヒント2: 温度で実効抵抗が変わる、または接続・計器が変わる可能性がある。
  • ヒント3: 抵抗器の温度、実際の端子電圧、抵抗値を時間とともに測る。

E4　NANDの契約を確認する

二入力NANDについて、真理値表の空欄を埋める。

ABY
00
01
10
11

次に、次の二つの文を分類する。

  • 「A=1、B=1ならYを論理0として読める」
  • 「A=1、B=1にした0.5 ns後、出力は必ず0.1 Vである」

後者を契約にするには、何の条件を追加しなければならないか。

ヒント
  • ヒント1: NANDはANDの結果を反転する。
  • ヒント2: 真理値表は電圧の具体値ではなく、論理値の結果を表す。
  • ヒント3: 電源、負荷、入力閾値、伝搬遅延、温度を考える。

E5　NANDの浮いた入力を診断する

NANDの入力Aをスイッチで切り離したところ、スイッチを開いたときに出力が0と1の間で不規則に変化した。Bは論理1へ固定されている。

  1. 真理値表だけでは、なぜこの観測を予測できないか。
  2. 台帳の成立条件のうち、どれが破られた可能性が高いか。
  3. 次の観測または修正を二つ提案する。
  4. 「NANDの契約が常に誤り」と結論してはいけない理由を書く。
ヒント
  • ヒント1: スイッチを開いた入力は、論理0とも論理1とも限らない。
  • ヒント2: 入力の電圧を測り、論理閾値と比較する。
  • ヒント3: 規定のプルアップまたはプルダウンを加え、安定してから出力を読む。

E6　RV32I ADDを手計算する

32ビットのRV32I ADDについて、次の結果を16進数で書く。

  1. 0x00000001 + 0x00000002
  2. 0xffffffff + 0x00000001
  3. 0x80000000 + 0x80000000

さらに、ADD x0, x5, x6を実行した後のx0の値を答え、なぜそのような契約が必要かを一文で説明する。

ヒント
  • ヒント1: 結果は(rs1+rs2) mod 2^32である。
  • ヒント2: 33ビット目は32ビット結果へ残らない。
  • ヒント3: x0は読み出すと常に0で、書き込み先にしても効果を持たない。

E7　ADD実装の故障を切り分ける

rv32eduのトレースに次が記録された。

instruction: ADD x7, x5, x6
before:      x5=1 x6=2 x7=0
after:       x5=1 x6=2 x7=4
  1. RV32Iの契約から予測されるx7を書き、どの不変条件が壊れたか説明する。
  2. ALUがSUBを選んだ、レジスタ番号を取り違えた、トレースを一命令早く読んだ、の三つを区別する追加観測を挙げる。
  3. x5=0xffffffff,x6=1のケースを追加したとき、何を確認できるか。
ヒント
  • ヒント1: 1+2は3であり、4ではない。
  • ヒント2: 命令ビット列、デコード結果、ALUの入力・演算種別・出力を分けて記録する。
  • ヒント3: 境界値は、加算と別演算、レジスタ幅の誤りを見つけやすい。

E8　Python整数と有限幅整数を比較する

次の値を比較する。

print(2**32 + 1)
print(2**100 + 1)
  1. Pythonの言語上の整数結果を、それぞれ十進数または2^n+1の形で書く。
  2. 同じ入力を32ビットADDの結果として扱った場合、どこで意味が変わるか説明する。
  3. 「Python整数は無限」と「CPythonは無限メモリを持つ」は、なぜ同じ文ではないか。
  4. 2つの処理系の内部表現を比較するとき、版情報と資源について何を記録するか。
ヒント
  • ヒント1: Pythonの上位契約では固定32ビットのラップを利用者へ見せない。
  • ヒント2: Python整数も有限のメモリと時間で実行される。
  • ヒント3: 内部の桁の基数や割当方法は実装依存なので、対象版を固定して観測する。

E9　同じ出力から実装を一意に決めない

次の二つのプログラムは、どちらも画面に3を表示した。

print(1 + 2)
a = 1
b = 2
print(a + b)
  1. 出力という上位の契約が同じでも、隠れている可能性のある下位表現を三つ挙げる。
  2. print(1 + 2)が定数3へ前計算されても、Pythonの意味を保てる条件を一つ以上書く。
  3. 二つのプログラムが同じCPU命令列だと、出力だけから断定できない理由を書く。
ヒント
  • ヒント1: AST、バイトコード、名前の読み出し、加算の時刻は別々に観測できる。
  • ヒント2: 観測結果が同じことと、内部経路が同じことは別である。
  • ヒント3: 計算を前倒しできるのは、値と副作用と例外などの観測結果を変えない場合だけである。

RV32I ADD
Python整数

次の故障を台帳のどの行・どの欄に記録するか分類し、最初に行う観測を一つずつ書く。

  1. 抵抗器の温度が上がり、電流が時間とともに変わった。
  2. NANDの入力が閾値付近に浮き、出力が揺れた。
  3. ADDの結果が境界値でだけ一致しない。
  4. 2**100の計算がメモリ不足で停止した。
ヒント
  • ヒント1: まず観測事実、次に期待、最後に条件を分ける。
  • ヒント2: 「契約違反」と「契約を適用できない条件」は同じとは限らない。
  • ヒント3: 追加観測は、仮説を最も小さく分けるものを選ぶ。温度、入力電圧、命令ビット列とALU、メモリ使用量などである。

合格の記録

次の全項目を、自分の言葉で記録する。

  • 四つの例に、下位表現、上位契約、隠される変数、成立条件、破綻条件、検証方法を入れた。
  • I=V/Rを抵抗器の条件付きモデルとして説明した。
  • NANDの真理値表と電圧波形・遅延を別に説明した。
  • RV32I ADDの有限幅とPython整数の違いを、境界値で説明した。
  • 一つの故障について、観測、期待、条件、分類、次の観測を分けて書いた。
