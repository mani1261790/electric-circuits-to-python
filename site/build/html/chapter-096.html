第96章　object、identity、type、value

96.1 三つの見方

Python objectは、memory上の一つの表現でありながら、identity、type、valueという三つの見方を持つ。identityは寿命中の同一性、typeは許される操作と構造、valueは比較や表示に使う内容である。a is bはidentity、a == bはtypeに定められたequalityであり、同じ答えを返すとは限らない。

MiniPyのobject headerはtype pointerまたはtype tag、参照管理情報候補、payload size、flagsを持つ。整数はpayloadへ値を入れ、BooleanとNoneは共有singletonとして表せる。singleton最適化を実装する場合も、identityの契約と整数valueの契約を別々にtestする。

96.2 objectの種類

integer objectは有限幅またはhost整数のどちらを使うかを固定する。Booleanはintegerのsubtypeとして扱うか専用typeとするかを明示し、暗黙変換を隠さない。string objectはbyte列かUnicode code point列か、長さの単位、終端NULの有無を記録する。

functionとclassもobjectになりうる。function objectはcode object、global環境、closure、呼出し可能性を参照し、class objectはinstanceのtypeとして働く。本章のMiniPy subsetではfunctionを扱い、classの全method resolutionやdescriptorは範囲外とする。

96.3 identityとequalityの表

a = 1000; b = 1000のidentityが同じかどうかを、整数valueのequalityから推論してはいけない。a = None; b = Noneはsingleton identityを共有する契約にできる。stringの同内容でも別allocationならidentityは異なりうる。test表には、object address/id、type、value、is、==、source_kindを入れる。

96.4 frame、heap、寿命

VM frameのlocal slotやoperand stackはobject pointerをrootとして保持する。heap object同士の参照は次章のallocationとGCへ渡す。objectをfreeした後にslotを使う、typeを壊れたpointerから読む、string lengthをpayload長と混同する、といった負の例を先に用意する。

固定runnerのaddressや出力は契約再生値で、CPythonのmemory addressを観測した事実ではない。object headerとMiniPy semanticsを分けて記述し、CPythonのreference countやinterningをそのままMiniPyの保証にしない。次章ではreference countとcycle GCでobjectの寿命を閉じる。

96.5 header、identity、frame rootを一つの表にする

int(3)、bool(True)、None、string payload [104,105]を、type_tag、flags、size、payload_pointerを持つheaderへ置く。string lengthをbytes単位=2と固定し、NUL終端なしというcontractを記録する。payloadの値が同じでも、別allocationならobject idは異なる。

状態表を自分で作る

本文を読み終える前に、次の五列を紙またはテキストへ写す。『層』『入力』『内部状態』『上位の契約』『破綻条件』である。層には物理量、数値模型、回路、命令、OS、処理系のどれかを入れ、同じ名前の量を別層で使うときは型と単位を併記する。

内部状態から上位の契約へ進むとき、隠した変数を一つ選ぶ。たとえば連続電圧を論理値へ写すなら、しきい値の近くの電圧と雑音を隠している。命令列を関数呼出しへ写すなら、レジスタやstack pointerを隠している。隠した変数が変化しても契約が保たれる範囲が、その抽象化の強さである。

次に、同じ表へ失敗時の値を書く。未定義電圧、負の容量、範囲外アドレス、stack underflow、権限違反などは、正常なゼロや空文字へ丸めない。失敗を早い層で止め、診断名と入力を保存しておくと、後で別の層の故障と取り違えにくい。

故障診断の手順

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • bad_type: 入力はunknown type tag。期待する診断はtype_rejectedで、正常値として続行しない。
  • bad_length: 入力はpayload length outside allocation。期待する診断はlength_rejectedで、正常値として続行しない。
  • freed_pointer: 入力はVM slot references freed object。期待する診断はlifetime_rejectedで、正常値として続行しない。
  • string_mismatch: 入力はheader length differs from payload。期待する診断はpayload_rejectedで、正常値として続行しない。
  • bad_identity: 入力はidentity lookup on absent object。期待する診断はidentity_rejectedで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

前後の章へ渡すもの

この章は独立した計算帳ではない。前から受け取った量を、次の層が読める契約へ変換する。

  • 受け取る: 前章で定義した入力を受け取る
  • 渡す: 次章へ検証済みの状態を渡す

渡す値には、値だけでなく単位、版、source kind、status、measuredフラグを付ける。後章で同じ記号が現れたとき、初出の定義と再利用の条件を辿れるようにする。

模型の境界を言葉にする

  • object表現はMiniPyのinteger/Boolean/None/string/function subsetに限定し、CPython struct layoutや全class protocolを再現しない。
  • host addressはidentityの例として扱うだけで、実行ごとの同一addressやinterningを保証しない。
  • object/header/identityの出力は固定runnerで契約を再生済みだが、CPython memory測定ではない。

境界を知ることは、式を弱めることではない。式が成立する条件を明示すれば、次により詳しい模型や測定へ進む理由を説明できる。逆に、条件を隠したまま桁の多い数値を出すと、精度ではなく誤解だけが増える。

章末の自己確認

最後に、代表実験を見ずに三つの文を書く。第一文は入力と単位、第二文は内部状態から出力までの一つの変化、第三文は最も近い破綻条件である。三文が書けたら、対応するartifactとrunnerの行を開き、本文の説明と同じtrace ID・statusになっているか照合する。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
