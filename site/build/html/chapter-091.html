第91章　syntax、semantics、PythonとCPython

91.1 sourceと意味を分ける

Python sourceは文字列だが、意味は文字列の見た目だけでは決まらない。lexical syntaxはtokenの並び、grammarは構文の形、static semanticsはcompile時に決める名前や文脈、dynamic semanticsは実行時の値と制御の規則を定める。これらを一つの「parserの動き」と呼ぶと、エラーの場所と責任が追えなくなる。

言語仕様は、どの実装でも守るべき観測可能な契約を記述する。CPythonはその契約を実装する一つの処理系であり、bytecode opcode、object layout、reference countなどは実装詳細である。同じsourceがCPythonの内部bytecodeと別処理系の内部表現で異なることは、直ちに言語仕様の違反を意味しない。

91.2 実行モデル

moduleを実行するとglobal namespaceが作られ、statementが順に評価される。function callは新しいframeとlocal namespaceを作る。name bindingはassignment、parameter、importなどで起き、未解決のnameは実行時に例外となる。例外は通常のreturnと別の制御移動で、途中のframeをunwindしてhandlerを探す。

objectはidentity、type、valueを持つ。isはidentity、==はequality operationであり、数値の等価とobjectの同一性を同一視しない。可変objectを共有した場合、aliasが見える値を変える。MiniPyでは扱うstatement、例外、object typeのsubsetを先に固定し、未実装機能をPython全体の意味として主張しない。

91.3 CPythonを観察する

同じsourceを、①source文字列、②token、③AST、④code object/bytecode、⑤実行結果、⑥例外という列で表にする。disやastの表示はCPythonの観測であって、言語仕様そのものではない。版を固定しない比較は、opcodeやAST fieldの変更を誤って意味の変更と呼ぶ。

比較表には、定数畳み込みの有無、evaluation order、name binding、例外型、出力を入れる。出力だけが一致しても、内部処理が同じとは限らない。逆に内部bytecodeが違っても、仕様上の評価順と結果が一致することがある。

91.4 MiniPyの契約

MiniPyは、整数、Boolean、None、assignment、if、while、function、printを対象候補とする。grammar、name resolution、stack effect、exceptionの対象をmanifestに書く。未対応のclass、generator、async、全built-inはout_of_scopeとして明示する。

この分離により、「Pythonとして正しい」と「MiniPyのsubset実装が正しい」を別のtestにできる。第92章ではsourceをtokenへ、第93章ではASTとscopeへ進む。各段階の入力と出力を保存すれば、parserの誤りをVMの誤りと取り違えない。

91.5 print(1 + 2)をsourceから意味まで追う

source文字列print(1 + 2)を、文字列→tokens→AST→bytecode→VM resultの5層へ分ける。ASTではCall(print, BinOp(1,+,2))となり、+は先に値を計算するが、AST構築時に3へ畳み込むかどうかは別のcompile policyである。source spanはline 1の列を保ち、各層のrecordへ渡す。

f(left(), right())では、まずcallee式fを評価し、その後に引数を左から右へ評価してから、関数本体を呼ぶ。このtoy traceでは意味の評価順をf,left,right、関数本体へのinvocation eventをleft,right,fとして別々に記録する。1/0はreturnではなくZeroDivisionErrorとunwind eventである。x=1; def f(): return xではxはmodule/global binding候補で、frame localと混同しない。

MiniPyはinteger、Boolean、None、assignment、if、while、function、printだけを対象候補とし、class、generator、async、全built-inはout_of_scopeにする。CPython 3.14系のbytecodeやobject layoutを比較しても、MiniPyが同一実装だという証明にはならない。固定runnerは契約入力から解析結果を再生済みだが、外部toolや実機の測定値ではない。次章のtokenizerへsource span付きで渡す。

状態表を自分で作る

本文を読み終える前に、次の五列を紙またはテキストへ写す。『層』『入力』『内部状態』『上位の契約』『破綻条件』である。層には物理量、数値模型、回路、命令、OS、処理系のどれかを入れ、同じ名前の量を別層で使うときは型と単位を併記する。

内部状態から上位の契約へ進むとき、隠した変数を一つ選ぶ。たとえば連続電圧を論理値へ写すなら、しきい値の近くの電圧と雑音を隠している。命令列を関数呼出しへ写すなら、レジスタやstack pointerを隠している。隠した変数が変化しても契約が保たれる範囲が、その抽象化の強さである。

次に、同じ表へ失敗時の値を書く。未定義電圧、負の容量、範囲外アドレス、stack underflow、権限違反などは、正常なゼロや空文字へ丸めない。失敗を早い層で止め、診断名と入力を保存しておくと、後で別の層の故障と取り違えにくい。

故障診断の手順

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • syntax_layer: 入力はmalformed source。期待する診断はsyntax_error_classifiedで、正常値として続行しない。
  • binding_layer: 入力はunresolved name。期待する診断はname_error_classifiedで、正常値として続行しない。
  • runtime_layer: 入力はinvalid operation。期待する診断はruntime_exception_classifiedで、正常値として続行しない。
  • implementation_claim: 入力はdiffering bytecode for same result。期待する診断はnot_spec_violationで、正常値として続行しない。
  • unsupported_subset: 入力はclass/generator/async in MiniPy。期待する診断はout_of_scope_rejectedで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
