第29章　物理状態からビットへ

29.1 この章の問い

電圧は連続量なのに、論理回路は0と1を扱う。これは電圧が本当に二つの値しか取るからではない。回路が「この範囲なら0」「この範囲なら1」と読む契約を置き、雑音やばらつきを含む物理状態の集合を重ならないよう設計するからである。

本章では、電圧分布、判定閾値、誤り率、雑音余裕を順に分ける。分布を数式で置くことは模型、閾値で0/1を返すことは判定契約、実際のヒストグラムは測定またはrunnerの出力である。ここに実データはなく、例の分布や誤り率は計算予定の入力である。

29.2 0と1は集合である

第25章のV_OLとV_OHは、出力が保証される境界を表した。受け手側ではV_IL以下を低い入力、V_IH以上を高い入力として保証する。従って、理想化した受信集合を

L = {v | v <= V_IL}、H = {v | v >= V_IH}

と書ける。間の区間は未定義であり、勝手に0または1へ入れない。出力集合と入力集合が接続できる条件は、低い信号についてV_OL <= V_IL、高い信号についてV_IH <= V_OHである。

これらの不等式は電圧の測定結果そのものではなく、インターフェースの論理契約である。負荷、温度、電源、入力数、測定点を指定して初めて、その契約を満たすか判定できる。

29.3 分布が重なるとはどういうことか

同じ論理値を何度も送っても、電源揺らぎ、熱雑音、製造ばらつき、前段の残留、測定器の分解能などで観測電圧は一点にならない。低い状態の観測を確率変数V_L、高い状態をV_Hとし、それぞれの分布をp(v|L)、p(v|H)とする。

二つの分布が完全に離れていれば、ある閾値で誤りなく分類できる。裾が重なれば、同じ閾値でも低い状態を高いと誤る確率と、高い状態を低いと誤る確率が生じる。分布の形を正規分布と仮定するのは便利な統計模型だが、半導体の自然法則が全ての回路で正規分布を要求するわけではない。

29.4 閾値と誤り率

判定器を、閾値V_decに対して

v < V_dec => 0、v >= V_dec => 1

と定義する。V_decは入力保証境界V_ILやV_IHと同じ記号ではなく、受信器が採用した判定規則である。未知領域を持つインターフェースでは、単一閾値で必ず安全に分類できるとは限らない。ヒステリシスや再試行がある場合は、その規則も保存する。

低い状態を高いと読む誤りをP(1|L)、高い状態を低いと読む誤りをP(0|H)とする。事前確率P(L)とP(H)を明示した総誤り率は

P_error = P(1|L)P(L) + P(0|H)P(H)

である。これは確率の定義から導く模型であり、実際の値は分布データとサンプル数がなければ計算できない。観測ゼロ件を「誤り率0」と報告するのも危険で、観測回数と上限の扱いを併記する。

29.5 雑音余裕との対応

雑音余裕は、分布の重なりを直接測った確率ではない。低い出力がV_OLまで上がっても受け手のV_IL以下に留まれる余地がNML = V_IL - V_OL、高い出力がV_OHから下がっても受け手のV_IH以上に留まれる余地がNMH = V_OH - V_IHである。

余裕が大きいほど、単純な静的電圧雑音に対して許容範囲が広い。しかし、雑音の時間幅、相関、電源変動、入力slew、温度、閾値分布を知らずに、NMLやNMHだけから誤り率を数値化してはいけない。雑音余裕は境界の距離、誤り率は分布と判定器の結果である。

29.6 離散分布の具体例と有限標本

分布の意味を曖昧にしないため、runnerへ渡す代表的な離散確率質量関数（PMF）を一つ固定する。低い状態は値[0.2, 0.4, 0.6] V、確率[0.2, 0.6, 0.2]、高い状態は値[0.4, 0.6, 0.8] V、確率[0.2, 0.6, 0.2]とする。各確率は0以上1以下で、合計が1になることを入力検査する。これは説明用の模型で、測定データではない。

判定をv >= V_decなら1とし、V_decを[0.3, 0.5, 0.7] Vと掃引する。この代表入力から、期待する条件付き誤りは順に

P(1|L) = [0.8, 0.2, 0.0]、P(0|H) = [0.0, 0.2, 0.8]

となる。事前確率をP(L)=P(H)=0.5と正規化しておけば、期待総誤り率はP_error = [0.4, 0.2, 0.4]である。ここで大切なのは結果の数字を覚えることではなく、PMFの裾を閾値の片側へ足し、priorを掛けてから足す順序である。

runnerで有限標本を扱うときは、状態ごとの試行数N、誤り数k、信頼水準confidence_level=0.95、片側か両側かを保存する。観測誤り率はk/Nだが、k=0でも真の確率が0とはいえない。片側Clopper–Pearson上限は、成功・失敗の二項モデルを採用するなら、上側確率uをBeta分布の逆関数で定める（k<Nではu = BetaInv(0.95; k+1, N-k)、k=Nではu=1）。これは有限標本に対する統計的な上限で、分布模型の正しさや実機の全条件を保証しない。

代表的な有限標本ケースをN=100、k=0、confidence_level=0.95、片側上限と固定する。このとき観測誤り率は0だが、Clopper–Pearson上限はu = 1 - 0.05^(1/100) ≈ 0.029513（約2.9513%）である。これは説明用の二項模型から得た解析予測であり、100回の実機試験を行ったという意味ではない。

29.7 予定する解析とrunner

計画では、低い・高い状態を表す二つの分布を、平均、幅、裾の扱いとともに入力し、V_decを掃引してP(1|L)、P(0|H)、P_errorを算出する。別の入力として、V_IL、V_IH、V_OL、V_OHからNML/NMHを計算し、確率と境界距離を同じグラフへ置く。

runnerの出力はnumeric_predictionであり、実機の波形やヒストグラムではない。測定を行う場合だけ、試行回数、サンプル条件、温度、電源、プローブ、欠測の扱いをmeasurementとして保存する。SPICEのモンテカルロ波形を使っても、それは指定model cardと乱数の計算であって、製造ロットの測定ではない。

29.8 負のテスト

V_OL > V_ILやV_OH < V_IHの順序違反、幅が負の分布、閾値が未指定、分母となる試行数が0、未知領域を自動的に低い側へ寄せる判定、SPICE予測を測定と表示する入力は失敗にする。少ない観測数を確実な誤り率として丸めることも失敗である。

誤り率が出ないときは、適当な0や1ではなくinsufficient_samples、invalid_voltage_order、threshold_missingなどの診断と、どの条件が欠けたかを返す。証拠が足りないことも結果の一種だが、成功結果ではない。

29.9 次章への橋

ここまでで、物理電圧を0/1の集合へ読むための境界と誤りを定義した。次章では、この0/1を電圧やトランジスタから切り離し、Boolean代数の演算規則として扱う。Booleanの恒等式が正しくても、実際の電圧分布や雑音余裕が自動的に保証されるわけではない。

まとめ

  • ビットは一点の電圧ではなく、判定される物理状態の集合である。
  • 分布の重なりは閾値と誤り率を必要にする。
  • 雑音余裕は境界距離であり、分布からの誤り率とは別の量である。
  • 解析・runner・SPICE・測定は証拠の種類とstatusを分ける。
  • 条件不足を数字で埋めず、診断としてfail closedにする。

境界を知ることは、式を弱めることではない。式が成立する条件を明示すれば、次により詳しい模型や測定へ進む理由を説明できる。逆に、条件を隠したまま桁の多い数値を出すと、精度ではなく誤解だけが増える。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。

11　次章の読者への引き継ぎ文

最後に、次章の読者がこの章を読み返さなくても前提を再構成できる引き継ぎ文を書く。第一文はこの章が固定した定義、第二文は代表入力と途中状態、第三文は守る不変条件、第四文は最も近い破綻条件、第五文は未実行または未照合の境界である。

引き継ぎ文の主語を『この値は』だけにしない。『この模型では』『この版のtoolでは』『このmemory領域では』『このsource spanでは』のように、値の所有者を明記する。所有者が変わるところが、章間のbridgeであり、独立レビューが最初に読む境界である。

引き継ぎ文を書いたら、manifestの bridge_in と bridge_out、handoffのopen question、required artifactを照合する。本文に書いた橋と台帳の橋が異なる場合は、どちらかを勝手に合わせず、差分を未解決として残す。
