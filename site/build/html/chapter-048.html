第48章　control、decode、memory map

第47章では、命令を実行するためのdatapathを、register file、ALU、memory、PC mux、write-back muxとして分けた。しかし、配線が存在するだけではCPUは動かない。命令ごとに「どのregisterを読むか」「ALUへ何を入れるか」「memoryを読むか書くか」「PCをどこへ進めるか」を決める必要がある。また、ALUが作ったaddressをどのmemoryやdeviceへ渡すかも、別の契約として決めなければならない。

本章ではcontrol unit（制御部）、decoder（デコーダ）、memory map（メモリ・マップ）、bus（バス）を一つの教育用CPUへつなぐ。対象はRV32Iの小さなsubsetとし、ROM、RAM、UARTを一つのaddress空間に置く。共通固定runnerは入力由来の契約を再生済みだが、HDLの外部実行とFPGA・実機測定は未実行である。本文の数値は代表入力から導いた期待値であり、実機で文字が出たとは言わない。

48.0.1　まず命令・制御・addressを分ける

この章を読む最初の表では、命令wordの解釈、datapathを動かすcontrol、memory map上のaddressを別欄にする。

層例失敗したときの診断

同じreadという単語でも、instruction decode、data bus、UART MMIOでは意味が違う。命令が正しく見えても、controlまたはaddressが誤っていればCPUの状態更新は正しくない。

48.1 命令を制御信号へ翻訳する

decodeは、32-bitのinstruction wordを、命令の種類とfieldへ分解する処理である。control unitはその結果をdatapathの制御信号へ変換する。例えばLW x5,0(x1)では、rs1の値とimmediateをALUへ入れてaddressを作り、memoryを読み、戻った値をx5へ書く。BEQではmemoryを触らず、二つのregisterを比較してPC選択だけを変える。

まず、制御信号を「動作を許す信号」と「選択する信号」に分ける。本章で使う主な信号は次の通りである。

信号意味
RegWrite次のclockでrdへwrite-backする
ALUSrcALUの第2入力をrs2にするかimmediateにするか
ALUOp加算、減算、比較などの演算を選ぶ
MemRead / MemWritedata busへのread/write requestを作る
MemToRegwrite-back値をALU結果とmemory結果のどちらにするか
PCSelPC+4、branch target、JAL target、JALR targetを選ぶ
Branch / Jumpbranch条件または無条件jumpを有効にする

decodeで認識できないopcodeや、認識したopcodeに対して許されないfunctを見つけたら、control signalを全部無効にし、illegal_instructionを付ける。未定義入力をたまたまALU加算として通すと、後段で「命令が動いた」ように見えてしまう。安全なdecoderは、既定値を無効にしてから、明示した行だけを上書きする。

代表wordをdecodeすると、例えば次のようになる。

この5行は、register field、immediate、命令class、control rowを一緒にtraceへ残す入力である。上のwordは説明用の入力で、RTL/HDLの実行結果ではない。共通固定runnerの契約artifactと、外部HDLのcycle traceは別の出所として記録する。

48.3 datapathの一命令を追う

命令fetchで得たwordをdecodeし、registerを読み、ALUまたはPC計算を行い、必要ならbusを経由して、最後にwrite-backする。単一cycle datapathでは概念上これらを一周期に通すが、busがreadyを返すまで停止する設計では、memory操作を複数cycleに分けてもよい。本章では比較を簡単にするため、教育用reference runnerは一つのin-flight transactionだけを許す。

LWの流れを具体化する。

  1. rs1=x1をregister fileから読み、12-bit immediateを符号拡張する。
  2. ALUを加算に設定し、address = x1 + immediateを作る。これは[式: affine_address]のbyte addressである。
  3. MemRead=1、MemWrite=0、wstrb=0000のread requestをbusへ出す。
  4. responseのrdataを受け、MemToReg=MEMとしてrdへ書く。
  5. branch/jumpでなければPCSel=PC+4を選ぶ。

SWでは4のwrite-backがない。rs2の値をwdataへ置き、命令のstore幅からwstrb=1111を作り、responseのerrorを確認してから命令完了とする。bus errorを無視して「storeは済んだ」とするのは、ROMへの誤書込みや未割当addressを隠す。

BEQでは、rs1とrs2を比較し、真ならPC + signed_offset、偽ならPC+4を選ぶ。JALはtargetへ移る前にPC+4をrdへ書き、JALRはrs1+immediateのtarget bit 0を0にしてからPCへ入れる。制御信号と、各muxの入力値の両方をtraceへ残すと、同じ結果に見える別のバグを区別できる。

48.4 memory mapはaddressの意味を固定する

CPUから見た0x80001020がRAMなのか、deviceなのかは、回路の外にある規約ではなく、このsystemのmemory mapで決まる。本章ではmachine-spec/rv32edu-memory-map.ymlの正本をそのまま使う。

regionstartend（exclusive）readwrite用途
ROM0x000000000x00010000yesnoreset vectorとprogram
RAM0x800000000x81000000yesyesdataとstack
UART0x100000000x10001000yesyesMMIO register

endをinclusiveにせずexclusiveにするのは、サイズの計算と隣接範囲の検査を一貫させるためである。例えば0x0000FFFFはROMだが、0x00010000はROM外である。RAMの先頭は0x80000000で、0x80001020はRAMに入る。0x20000000はどの範囲にも入らないので、readでもwriteでもunmapped_addressにする。

decoderはアドレスを範囲比較へ通し、region hitを一つだけ作る。複数hit、hitなし、または権限違反はerrorとする。ROMへのstoreはread_only_region、unmappedへのaccessはunmapped_addressであり、同じ「返ってこない」という扱いにまとめない。エラーの種類があれば、trapを実装する次章でcauseへ対応づけられる。

本章のmapはcacheや仮想記憶を持たない物理addressの教育用モデルである。正本にはtimer（0x10001000〜0x10001FFF）も予約されているが、本章の実験対象はUARTに限定し、timerの動作を検証したとは主張しない。実際のSoCでは、複数のbus階層、cache、MMU、security属性、device固有の待ち時間が加わるが、それらをここへ暗黙に含めない。

48.5 busはvalidとreadyでtransferを合意する

master（ここではCPU）がrequestを出し、slave（ROM、RAM、UART）がresponseを返す。本文では短い名前を使うが、正本bus仕様の信号との対応を固定する。valid= req_valid、ready= req_ready、write= req_write、address= req_addr、wdata= req_wdata、wstrb= req_wstrb、rvalid= rsp_valid、rdata= rsp_rdata、error= rsp_errであり、応答側のrsp_readyもrunner入力として保持する。最低限の信号は次の通りである。

信号送信元意味
validmasterこのcycleのrequest欄が有効
readyslaveこのcycleに受理できる
writemaster1ならstore、0ならload
addressmasterbyte address
wdata / wstrbmasterwrite値と有効byte lane
rvalid / rdataslaveread responseと値
errorslavedecode、権限、device側の失敗

transferはvalid && readyが同時に1になったcycleに一回だけ成立する。validを1にしたままreadyが0なら、masterはaddress、write、wdata、wstrbを保持する。readyが1になったcycleに受理し、one-outstanding契約では次のrequestを出す前にresponseを待つ。

代表的なread時系列は次の通りである。

cyclevalidreadyaddress意味

ready=1だけではtransferではなく、valid=1だけでもtransferではない。valid=0, ready=1を受理数へ加えると、idle cycleをloadとして数えることになる。逆に、受理後もvalidを解放しないmasterを許すと、同じUART文字を二度書いたり、同じstoreを二度実行したりする。runnerのtraceにはrequest id、accept cycle、response cycle、errorを含める。

48.6 UARTはMMIOとして扱う

UARTはCPUから特別な命令で見えるのではなく、決められたaddressへload/storeするdeviceである。ここではUART regionのoffset 0をdata register、offset 4をstatus registerとする。SW x6,0(x5)でx5=0x10000000、x6=0x00000041なら、通常のstore decodeを通ったrequestがUART data registerへ届き、wdataの低位byte 0x41を一つ受理する。

この処理に必要なのは、次のような契約である。

address = 0x10000000
write   = 1
wdata   = 0x00000041
wstrb   = 1111
accept  = valid && ready
effect  = accepted_data_byte = 0x41

ここでeffectはbusが受理したという論理上の結果で、端末画面に文字Aが表示されたという測定ではない。baud rate、TX FIFO、CTS/RTS、電圧波形、外部端末の受信は別の層である。MMIO writeのdirected testは、address decode、byte enable、accept cycle、UART data registerの更新を確認し、未接続端末の表示を合否条件にしない。

48.7 directed testとtraceの設計

directed test（指向試験）は、入力、実行順、期待状態を先に固定する試験である。乱数を増やすより先に、制御信号の一行とmemory mapの一範囲を確実に通す。最小の一連の試験は次のようになる。

1. PC=0x00000000からADDIでRAM addressを作る
2. LWで0x80001020の0x12345678をx5へ読む
3. BEQのtaken/not-takenを一回ずつ通る
4. SWでRAMへ0xA1B2C3D4を書き、byte列を確認する
5. JALRでtarget bit 0をclearして戻る
6. UART data registerへ0x41をstoreする

各命令で最低限、pc、raw instruction word、decoded class、control signal、register read、ALU inputs/result、bus request、bus response、register write、next PCを保存する。load/storeではaddressとwstrb、branchでは比較結果と選択target、jumpではlinkも保存する。reference runnerとHDLのtraceを比較する場合も、同じ入力と同じbyte orderを使用する。

期待値を「実行結果」と「出所」に分ける。例えば、0x80001020から78 56 34 12をlittle-endianで読むと0x12345678になることは解析上の期待値である。一方、Verilatorが出したJSONは外部toolのrunner outputであり、実機のbus信号やFPGAのUART波形ではない。外部HDLが未実行の間はstatus: planned、measured: false、accessed_for_this_draft: falseを維持し、共通固定runnerのexecuted_analyticとは別欄に置く。

48.8 故障を信号の層で切り分ける

「UARTから文字が出ない」という症状だけでは、decoder、control、address map、bus、UARTのどこが悪いか分からない。次の順にtraceを調べる。

  1. instruction wordが期待したclassへdecodeされたか。
  2. RegWrite、ALUSrc、MemWrite、PCSelがcontrol tableの行と一致するか。
  3. ALUがbyte addressを正しく作ったか。
  4. address decoderがROM/RAM/UARTの一つだけを選んだか。
  5. valid && readyが一回だけ成立したか。
  6. UART requestのwstrbとdata byteが正しいか。

例えばready=1だがvalid=0のcycleを受理すると、idle中にUARTへ書いたことになる。ROMのstoreを黙って捨てると、programの破壊を検出できない。未知wordをNOPとして実行すると、illegal instructionを次章へ渡せない。各失敗は「停止したか」だけでなく、固有のerrorとsource_kindを持つべきである。

48.9 次章への橋

ここまでで、RV32I instruction wordはcontrol signalへ分解され、datapath、bus、memory map、UART MMIOを通る一つの状態遷移になった。ROM、RAM、UART、unmappedを同じaddress軸へ置いたので、次は不正命令、bus error、timer、外部deviceの事象をCPUの制御へ戻せる。

第49章では、illegal instructionとinterruptをtrap entryへ接続する。そこでは本章のerror、PC、memory map、traceを、mcause、mepc、mtvecの保存契約と対応づける。実行前の予定artifactを実測値へ昇格させるには、runner、HDL、source gate、独立レビューをすべて通す必要がある。

control、decode、memory mapの計算を、結果だけでなく途中の状態から再構成する。以下では、各実験を同じ順序で読む。順序をそろえることで、物理の積分、回路の連立方程式、命令の状態遷移、処理系のstack操作を同じ観測方法で比較できる。

0　共通の書式

最初の行に入力と単位、二行目に使う式または遷移規則、三行目に途中状態、四行目に出力、五行目に検証条件を書く。五行を書けない場合は、本文の式・表・仕様のどれかがまだ手元にない。数値を計算機へ渡す前に、符号、桁、基数、配列の添字、アドレス幅を声に出して確認する。

例題1　instruction decode and control

48.実践ケースブック　宣言から観測へ

このケースブックは、control、decode、memory mapの中心問題「32-bit命令から、register読出し、ALU操作、memory access、書戻しを制御する信号をどう生成するか。」を、manifestに宣言された入力から追い直すための作業欄である。本文の結論を写すのではなく、入力、途中状態、出力、境界、出所の順に自分で埋める。ここにない値を補ってはいけない。

5　模型の境界と章間の橋

この章の模型は、適用範囲を明示して初めて安全に使える。次の限界を一つずつ、本文のどの主張に効くかと一緒に読む。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
