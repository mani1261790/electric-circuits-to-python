第47章　単一cycle datapath

第46章では、RV32Iの命令をassemblyとして並べ、register、stack、memory、PCが一命令ごとにどう変わるかを追った。次に必要なのは、その一命令を実際の配線へ落とすことである。第47章では、命令fetchから結果の書戻しまでを一つのclock周期に通す単一cycle datapath（単一周期データ経路）を作る。

ここでいう一周期は「すべての命令が同じ計算量である」という意味ではない。ADDはregisterを読み、ALUで加え、registerへ戻す。LWはさらにaddressを作ってdata memoryを読み、BEQは比較結果で次のPCを選ぶ。異なる経路を一つの周期へ重ね、命令ごとにcontrol signalとmuxの選択を変える。周期の終わりにだけarchitectural stateを更新するので、途中の組合せ信号を次の命令の状態と取り違えない。

47.1 一周期の入口と出口

47.1.1　まずstate・control・writeを一行にする

一周期を読む最初の表では、edge前のarchitectural state、decodeが作るcontrol、edgeで確定するwriteを分ける。

組合せ信号を途中で見ただけでは、registerやmemoryが更新されたとは言えない。LWやBEQでも同じ欄を作ると、write-back、memory side effect、next-PC選択の違いが見える。

本章の最小状態は、32-bitのPC、32本の32-bit register、instruction memory、data memoryである。clock edgeの直前を状態S_n、直後をS_{n+1}と書く。一周期中の組合せ論理はS_nとfetchした命令を入力に取り、次のPC、register write、memory writeを計算する。edgeで有効なwriteだけを状態へ反映する。

decodeは32-bit instructionをopcode、rd、rs1、rs2、funct field、immediateへ分解し、datapathの選択信号を作る。本章のcontrol表は次のように固定する。

—はその信号を使わないという意味であり、任意の値を安全に流してよいという意味ではない。未定義opcodeでreg_writeやmem_writeを1にしない。decodeが失敗したらillegal_instructionとして停止するか、少なくともすべてのside effectを無効にする。後者を採る場合も、停止・faultの規則をtraceへ記録する。

ALUの入力第二項は、R-typeならrs2、I/S-typeなら符号拡張immediateでmux選択する。BEQの比較は、rs1-rs2=0というALU結果のzeroを使う実装と、等値比較器を別に置く実装がある。どちらも、比較信号がbranch controlへ届く前に次のPC muxを選べることが条件である。内部の部品数はISAが固定しないが、信号の意味とedgeで見える結果は固定する。

47.3 ADDの経路を数値で追う

PC=0x00001000、命令がADD x5,x6,x7、x6=10、x7=3とする。decodeの出力はrd=5、rs1=6、rs2=7、reg_write=1、alu_src_imm=0、alu_op=addである。register fileは二つのread dataを同じ周期に出し、ALUは13を作る。write-back muxはALU側を選び、edgeでx5へ13を保存する。PC muxはsequential側を選び、PC_next=0x00001004とする。

数式としては、ALU結果を式(47-1)で表す。

alu_result = (rs1_value + operand2) mod 2^32                         (47-1)
operand2 = rs2_value                    (R-type)
         = sign_extend(immediate)       (I/S-type)

式(47-1)の単位は32-bit register wordで、数学的整数の無限精度の和ではない。0xFFFFFFFF+1なら結果は0x00000000となる。carryを別出力にするかどうかはこのsubsetのarchitectural contractに含めないので、ALU内部のcarryを勝手にflag registerへ保存しない。

これは単なる足し算の計算例ではない。rs1とrs2を逆に読む、rdを一つずらす、reg_writeを次の命令へ遅らせると、同じ最終値に見える短いprogramでもinstruction-by-instruction traceが違う。traceには少なくともpc、raw word、decoded fields、control、read values、ALU result、write-back、pc_nextを残す。

47.4 LWとSWはdata memoryを一周期へ置く

x6=0x00002000、x5=0xDEADBEEF、offset=8とする。これはdatapathのアドレス計算だけを見る抽象toy memory domainで、rv32eduの物理memory mapは第48章で導入する。SW x5,8(x6)では、ALUが0x00002008を作り、store data muxがx5を選ぶ。edgeでmemory write enableとbyte enableが有効なら、little-endianの4 byteをEF BE AD DEの順で保存する。register writeは0である。

次のLW x7,8(x6)では、同じaddressから4 byteを読み、load dataをwrite-back muxへ通し、edgeでx7へ0xDEADBEEFを書く。LWのaddress生成とSWのaddress生成は同じALU経路を共有できるが、書く先は異なる。mem_write=1なのにreg_write=1も残すと、store命令がrd fieldの偶然の値へ書き込む。

memory readを組合せとしたのは、本章で「一周期に通す配線」を観察するための仮定である。実際のmemoryがread latencyを持つなら、LWを同じedgeで完了できない。valid-ready、wait、pipelineなどを加えた時点で、制御状態と周期数を新しい契約にする。data memoryをPython辞書で置き換えた予定traceを、FPGAのBRAM latencyや実機のbyte lane測定と呼んではならない。

47.5 branchとjumpは次のPCを選ぶ

sequential targetは常にPC+4である。BEQ x5,x6,+16では、比較が真ならPC+16、偽ならPC+4をPC muxへ送る。PC=0x1000ならそれぞれ0x1010と0x1004である。比較対象とoffsetを正しく読んでいても、target加算器へ現在のPCでなくPC+4を入れると4 byteずれるので、traceのpc_baseとtargetを別欄にする。

JAL x1,+32は、x1=PC+4=0x1004を書き、PC_next=0x1020を選ぶ。JALR x1,0(x5)でx5=0x2001なら、加算結果は0x2001でもPCへ入れるtargetはbit 0をclearした0x2000である。C拡張なしのRV32Iでは4-byte境界も検査するため、raw target 0x2002はbit 0 clear後も0x2002に留まり、instruction-address-misalignedとして受理しない。link writeとPC selectを同じjump信号だけで曖昧に制御せず、link_value、target_value、rd、reg_writeをtraceへ保存する。

branchとjumpのtarget選択は組合せ回路で決まるが、PCそのものの更新はclock edgeで行う。PC muxの出力が不定のままedgeを越えた場合、分岐がたまたま正しく見えたとしても合格にしない。alignment違反、未定義opcode、reset中のPC更新はfail closedにする。

47.6 命令列を一周期ずつ比較する

単一cycleの説明を部品図だけで終わらせず、第46章のassembly traceと対応づける。代表programを次のようにする。

    addi x6, x0, 10       # x6 = 10
    addi x7, x0, 3        # x7 = 3
    add  x5, x6, x7       # x5 = 13
    sw   x5, 8(x0)        # mem[8..11] = 13
    lw   x8, 8(x0)        # x8 = 13

参照模型の各stepは、(1) 実行前PC、(2) raw wordとdecode、(3) control、(4) register read、(5) immediateとALU入力、(6) ALU/memory結果、(7) registerまたはmemory write、(8) next PCを一行にする。期待されるPCは0x00000000、0x00000004、0x00000008、0x0000000C、0x00000010で、最後のPC_nextは0x00000014である。これは手計算で定義した契約であり、共通runnerは入力由来の契約再生artifactを保存する。ただし、ここに示した列はRTL/Verilatorのcycle traceやFPGA上の観測結果ではない。

RTLを作る場合、同じ入力programをVerilatorでcycle traceへ変換し、reference JSONと命令IDごとに比較する。最終registerだけでなく、reg_write、mem_write、address、write-back選択、PC mux選択を比べる。最終値だけが一致しても、storeが別addressへ一度書いてから上書きしたバグ、branchで不要な命令を一度実行したバグを見逃す。

47.7 失敗を層に分ける

ADDの値が違う場合は、まずraw wordとdecode field、次にregister read、ALU operand mux、ALU、write-back、最後にedge更新の順に確認する。LWだけ違う場合は、address、alignment、byte enable、endianness、memory read latencyを分ける。BEQだけ違う場合は、比較結果、immediate復元、PC base、target加算、PC muxの順に分ける。

典型的な失敗は次の通りである。

負のテストは、正しい入力の成功例よりも、配線の責任を明らかにする。例えばLWでwb_from_mem=0にする、BEQの比較を反転する、SWでreg_write=1にする、x0へwriteを許す、PC muxのdefaultを未定義にする、といった故障を一つずつ注入する。診断結果には「どのcontractを破ったか」と、入力・期待error・statusを保存する。

47.8 実験・実装の境界

本文の代表値は、式と指定入力から得た解析上の期待値である。共通runnerの入口はbook run 47 <experiment-id>とし、参照Python、SystemVerilog/Verilator、必要ならYosysのformal checkを別artifactへ保存する。ここで作るRTLはRV32Iのsubsetであり、cache、例外、pipeline、同期memory、MMIOは含めない。

FPGAは任意経路として、合成、place-and-route、timing report、bitstream、reference boardのpinとclock constraintを別々に記録する。bitstreamを作っていない段階でclock周波数やboard上の電圧を主張しない。SPICEも、単一cycleのarchitectural traceを検証する道具ではないので、本章の標準実験には含めない。planned、measured:false、accessed_for_this_draft:falseを各成果物に残す。

47.9 次章へ

単一cycle datapathは、PC、instruction memory、decode、register file、immediate、ALU、data memory、write-back、next-PC muxを一周期の組合せ経路へ置き、edgeで状態を更新する。命令ごとに必要なcontrol signalが違うので、次章ではdecodeとcontrolを独立した表・論理へ切り出し、memory mapとbusの境界を加える。

第48章へ渡すものは、命令ごとのreg_read、alu_op、mem_read、mem_write、wb_select、branch/jump、PC target、そして未定義命令時のside effect禁止である。この表を共通にしないままcontrol unitを作ると、単一cycle datapathの正しさを命令列ごとに再発明することになる。

故障診断の手順

故障は、入力、計算、表現、境界、出所の五分類で調べる。まず入力が有限で単位付きかを見る。次に計算の符号、係数、添字、丸めを確認する。その後、出力の表現幅、アドレス、状態名、source kindを確認する。最後に、予測を測定と呼んでいないか、上流の失敗を隠していないかを確認する。

  • store_register_side_effect: 入力はmem_write=1 and reg_write=1 for SW。期待する診断はstore_must_not_write_registerで、正常値として続行しない。
  • wrong_writeback_source: 入力はwb_from_mem=0 for LW。期待する診断はload_must_write_memory_dataで、正常値として続行しない。
  • branch_base_error: 入力はbranch target computed from PC+4。期待する診断はbranch_target_uses_current_pcで、正常値として続行しない。
  • jalr_bit0: 入力はJALR raw target is odd and bit0 is retained。期待する診断はjalr_bit0_clear_requiredで、正常値として続行しない。
  • jalr_bit1_no_C: 入力はC拡張なしでJALR target bit1が1のまま。期待する診断はinstruction_address_misalignedで、正常値として続行しない。
  • x0_write: 入力はreg_write enabled with rd=x0。期待する診断はx0_remains_zeroで、正常値として続行しない。
  • illegal_side_effect: 入力はunknown opcode with default mem_write=1。期待する診断はillegal_instruction_has_no_side_effectで、正常値として続行しない。
  • memory_latency_mismatch: 入力はsynchronous BRAM attached to zero-latency LW path。期待する診断はmemory_latency_contract_mismatchで、正常値として続行しない。
  • trace_as_measurement: 入力はplanned reference/RTL trace labeled as board measurement。期待する診断はsource_kind_mismatchで、正常値として続行しない。

失敗を再現するときは、一度に一条件だけを変える。二つ以上を同時に変えると、どの境界が効いたか分からなくなる。エラーメッセージだけでなく、入力hash、章・実験ID、上流artifactの状態も保存する。

模型の境界を言葉にする

  • RV32I baseのADD、ADDI、LW、SW、BEQ、JAL、JALR subsetだけを扱い、例外、cache、pipeline、MMIOを含めない。
  • instruction memoryとdata memoryは一周期の組合せreadという教材仮定で、同期BRAMのlatencyを含めない。
  • 単一cycleの結果と契約traceは固定runnerの再生artifactである。RTL・formal・FPGA・実機は未実行である。
  • FPGAは任意経路であり、合成、配置配線、timing、bitstream、実機のclock・電圧を測定したとは主張しない。

境界を知ることは、式を弱めることではない。式が成立する条件を明示すれば、次により詳しい模型や測定へ進む理由を説明できる。逆に、条件を隠したまま桁の多い数値を出すと、精度ではなく誤解だけが増える。

8　ひとつの値を最後まで追う

この章で最も小さい代表入力を一つ選び、上位の問いから下位の実装へ、また下位の結果から上位の契約へ往復する。値の名前が層ごとに変わるときは、同じ行に別名を並べ、同一視してよい条件を右側に書く。

最初の行には、入力の出所と固定版を書く。二行目には、本文で導入した式または状態遷移を一つだけ置く。三行目には、式を評価する前の中間状態を書く。四行目には、計算後の値と残差を書く。五行目には、上位の契約へ戻るための不変条件を書く。

単位を持つ量は、数値の横へSI単位または宣言した単位系を必ず付ける。bit列は幅と符号解釈を付け、アドレスは対象memory領域を付ける。状態名は初期状態と更新順を付ける。tokenやASTはsource spanを付ける。これらを省略した値は、数字が同じでも別のcaseである。

途中で予測と結果が異なったら、最後の行から修正しない。入力、仮定、更新、表現、実行環境の順に一つずつ戻り、最初に不一致になった行へ診断名を付ける。診断名を付けられない差は、未解決として後段へ渡さない。

9　逆向きに説明する

今度は出力から出発し、どの入力と規則が必要だったかを逆向きに書く。画面の文字、論理値、レジスタ値、電圧、エネルギーのように異なる表現を、途中のartifactなしで直接つないではいけない。各矢印のそばに、保証する契約と保証しない詳細を一つずつ書く。

逆向きの説明で最初に見つかる欠落は、たいてい三種類のどれかである。入力の単位または幅がない、モデルの適用条件がない、または実行と測定の境界がない。この章の本文へ戻り、欠落を埋める行を一つ追加する。

10　再現記録の最小形

再現記録には、章ID、実験ID、case、入力hash、toolまたはmodelの版、終了コード、出力artifact、source_kind、status、measuredを残す。時刻やhost名は再現性の補助情報であり、計算値や状態遷移の一部として扱わない。

この最小形を満たせないときは、実験が難しいのではなく、契約がまだ閉じていない。閉じていない契約は、成功結果を保存するより先に、未指定欄と診断欄を保存する。
